Đưa MetaBoard lên production

Web ở Vercel, API ở Render, Postgres ở Supabase, giọng đọc ở VieNeu cloud. Làm đúng thứ tự dưới đây; mỗi bước đều có lệnh kiểm tra ngay tại chỗ để không phải đoán xem bước trước đã đúng chưa.

  • Next.js → Vercel
  • Express → Render
  • Postgres → Supabase
  • TTS → VieNeu cloud

0 Chuẩn bị (10 phút)

Chỉ cần làm một lần. Thiếu mục nào thì bước tương ứng sẽ dừng.

  • Repo đã push lên GitHub, nhánh main (repo hiện tại: kingsley1996/meta-board-tft).
  • Tài khoản Vercel, Render, Supabase.
  • Thẻ thanh toán cho Render — service dùng plan Starter, không dùng free (free ngủ sau 15 phút, trang public gọi API phía server sẽ chậm hoặc lỗi).
  • Email + mật khẩu mạnh cho account admin đầu tiên.

Ba API key cần lấy trước

KeyLấy ở đâuDùng cho
DEEPGRAM_API_KEY console.deepgram.com → API Keys → Create Key Nhận dạng giọng nói (STT) tiếng Việt; đồng thời là engine TTS dự phòng
GOOGLE_API_KEY aistudio.google.com/apikey LLM cho Coach AI (ASSISTANT_PROVIDER=google đã đặt trong blueprint)
VIENEU_TTS_API_KEY vieneu.io → đăng ký → tạo key vn_sk_… Đọc câu trả lời (engine chính trong cấu hình này)
Cảnh báo Key thử nghiệm của VieNeu (vn_test_…) bị giới hạn 100 từ và 30 request/ngày. Đã đo thực tế: chạm trần thì mọi request trả 429. Đừng dùng key thử cho production — hoặc nâng cấp, hoặc đổi TTS_PROVIDER=deepgram tạm.

Tạo token cho cron

openssl rand -hex 32

Lưu kết quả thành REFRESH_TOKEN — dùng cho cả service API và cron refresh.

1 Supabase — tạo Postgres (5 phút)

  1. Vào supabase.com/dashboard → New project.
  2. Đặt tên metaboard, region Southeast Asia (Singapore), mật khẩu database mạnh. Lưu mật khẩu này.
  3. Đợi project chuyển sang Active (khoảng 2 phút).
  4. Vào Project Settings → Database → Connection string → Connection pooling, chọn Session mode, copy nguyên URI:
postgres://postgres.<ref>:<password>@aws-0-ap-southeast-1.pooler.supabase.com:5432/postgres?sslmode=require

Đây là DATABASE_URL. Giữ nguyên ?sslmode=require — driver đọc được, không cần sửa code.

Đừng chọn Direct connection db.<ref>.supabase.co:5432 là IPv6-only; Render không có IPv6 nên API sẽ không bao giờ kết nối được. Transaction mode :6543 thì cắt prepared statement, cursor và session state — code này có transaction giữ client và DDL lazy lúc chạy, nên chỉ Session mode :5432 là đúng.
Ghi chú Nếu tự ghép URL thay vì copy: URL-encode mật khẩu — key random của Supabase chứa +, /, % và sẽ làm URL sai.

2 Seed dữ liệu lần đầu (5 phút)

Chạy từ máy local, trỏ vào DB Supabase. DB đang trắng nên đây là lần duy nhất cần seed.

cd ~/ai-projects/tft-comps

DATABASE_URL='postgres://postgres.<ref>:<password>@aws-0-ap-southeast-1.pooler.supabase.com:5432/postgres?sslmode=require' \
ADMIN_EMAIL='you@example.com' \
ADMIN_SEED_PASSWORD='<mật-khẩu-mạnh>' \
npm run seed --workspace @metaboard/api

Kỳ vọng: log tạo schema, đồng bộ game data và nạp comps/guides, không có cảnh báo ADMIN_EMAIL/ADMIN_SEED_PASSWORD not set.

Chỉ chạy một lần Seed thay thế toàn bộ comps và guides. DB đã có nội dung tạo qua /admin thì tuyệt đối không seed lại — mọi thứ soạn tay sẽ mất, log vẫn báo thành công. Patch day chỉ gọi POST /api/tft/refresh.
Ghi chú ADMIN_EMAIL và ADMIN_SEED_PASSWORD phải trùng với giá trị bạn nhập ở Render (bước 3): lúc API khởi động, nó “adopt” account admin đã tồn tại thay vì tạo account thứ hai.

3 Render — dựng API + cron (10 phút)

  1. Vào dashboard.render.com → New + → Blueprint.
  2. Connect GitHub, chọn repo này, nhánh main → Apply.
  3. Render đọc render.yaml và tạo hai resource:
    • metaboard-api — web service, plan Starter, region Singapore, health check /api/health, auto deploy khi push.
    • metaboard-tft-refresh — cron 12:00 UTC (19:00 giờ Việt Nam), gọi /api/tft/refresh.

Bấm Deploy Blueprint và đợi log có metaboard server on http://… cùng health check xanh. Sau đó copy URL service (dạng https://metaboard-api.onrender.com, có thể có hậu tố).

Kiểm tra ngay

curl -s -o /dev/null -w '%{http_code}\n' https://<api>.onrender.com/api/health
curl -s https://<api>.onrender.com/api/health/ready

/api/health phải trả 200. /api/health/ready trả 200 kèm số comp — nếu 503 thì DATABASE_URL sai hoặc đang dùng direct/transaction mode.

Cron Cron chưa chạy được cho tới khi có API_ORIGIN và REFRESH_TOKEN trong env của chính cron — làm ở bước 5. Nó không chặn deploy API.

4 Vercel — dựng web (10 phút)

  1. Vào vercel.com/new → import repo GitHub.
  2. Root Directory: để trống (gốc repo). Đây là chỗ hay sai nhất — chọn apps/web là @metaboard/shared không resolve được, vì npm workspaces phải install từ gốc.
  3. Framework Preset: Next.js (Vercel tự nhận từ vercel.json). Không sửa install/build/output — vercel.json đã khai npm ci → npm run build --workspace @metaboard/web → apps/web/.next.
  4. Thêm Environment Variables cho Production:
BiếnGiá trịVì sao
BACKEND_URL https://<api>.onrender.com Đích của rewrite /api/* và của các lệnh server-side
SITE_URL https://<project>.vercel.app sitemap.xml, robots.txt, canonical URL
Bắt buộc BACKEND_URL phải có trước khi build, không chỉ lúc chạy: Next biên dịch rewrite vào build output, và server components gọi thẳng API. Thiếu hoặc sai → build vẫn xanh, site 500 lúc chạy.

Bấm Deploy, đợi khoảng 2–4 phút, rồi copy domain production.

Nếu chưa biết domain Vercel trước lúc build: đặt SITE_URL tạm, deploy, lấy domain thật rồi sửa và redeploy — chỉ ảnh hưởng sitemap/canonical, không ảnh hưởng API.

5 Nối hai đầu (5 phút)

Sau bước này web mới đăng nhập được và cron mới chạy đúng.

  1. Render → metaboard-api → Environment: sửa AUTH_WEB_ORIGIN thành domain Vercel thật (https://<web>.vercel.app). Save — Render tự redeploy.
    Biến này là gốc của link xác minh email và OAuth redirect; để sai thì link trỏ về example.vercel.app.
  2. Render → metaboard-tft-refresh → Environment: đặt API_ORIGIN=https://<api>.onrender.com và REFRESH_TOKEN cùng giá trị với service API.
  3. Chỉ khi dùng Google OAuth: Google Cloud Console → OAuth client → Authorized redirect URI thêm https://<web>.vercel.app/api/auth/google/callback, rồi nhập GOOGLE_OAUTH_CLIENT_ID / GOOGLE_OAUTH_CLIENT_SECRET vào Render. Không dùng OAuth thì bỏ qua.
Xong Từ đây mọi push lên main tự deploy: Render cho API, Vercel cho web. Không cần build tay.

6 Kiểm tra sau deploy (10 phút)

Chạy hết bảng này trước khi gửi link cho ai. Cột “kỳ vọng” là điều kiện dừng.

KiểmKỳ vọng
curl -s https://<api>/api/health/ready 200 + số comp > 0. Số 0 nghĩa là bước 2 chưa chạy.
curl -s https://<api>/api/comps 200, JSON comps của patch hiện tại.
curl -s https://<api>/api/voice/tts/status {"available":true,"provider":"vieneu","primary":"vieneu",…}. Nếu false: reason chỉ có ở dev, nên xem log Render — tts_unavailable là thiếu URL/key, tts_credentials_rejected là key sai.
curl -s https://<api>/api/voice/status available: true + danh sách provider STT có key. false = thiếu toàn bộ key STT.
curl -sI https://<web>/en 200. Mở cả /vi, console không có lỗi, không request ra domain lạ.
curl -s https://<web>/api/health 200 — chứng minh rewrite Vercel → Render hoạt động.
curl -s https://<web>/sitemap.xml | head URL là domain thật, không phải localhost:4173.
Đăng nhập https://<web>/en/login bằng ADMIN_EMAIL Vào được /admin; account thường bị đá về login.
curl -X POST https://<api>/api/tft/refresh (không token) 401. 503 nghĩa là REFRESH_TOKEN chưa được cấu hình.
curl -X POST -H "Authorization: Bearer $REFRESH_TOKEN" https://<api>/api/tft/refresh 200; gọi lại ngay thì 409 a refresh is already running — đúng thiết kế.
PLAYWRIGHT_BASE_URL=https://<web> npm run test:e2e E2E xanh trên deployment thật.
Cookie Sau khi đăng nhập, mở DevTools → Application → Cookies: mb_session phải có Secure và SameSite. Nếu đăng nhập xong vẫn như chưa đăng nhập, kiểm tra bạn đang mở đúng domain Vercel (không gọi thẳng domain Render) và site chạy HTTPS.

7 Mailer — việc còn nợ trước khi mở đăng ký

Hiện tại chưa có mailer production. Điều đó có nghĩa là:

  • getMailer() throw khi NODE_ENV=production; không có console mailer để rò link xác minh ra log host.
  • Đăng ký / đăng nhập vẫn chạy vì AUTH_REQUIRE_EMAIL_VERIFICATION đang để trống (= false): đăng ký là tự xác minh.
  • Không có luồng reset mật khẩu qua email trong code hiện tại. Quên mật khẩu = sửa trực tiếp trong DB hoặc thêm mailer.
Đừng bật sớm Không đặt AUTH_REQUIRE_EMAIL_VERIFICATION=true trước khi cắm mailer thật: route đăng ký sẽ 500 vì getMailer() ném lỗi.

Khi có mailer (Resend / Postmark / SMTP)

  1. Implement interface Mailer trong apps/api/src/mailer.ts và trả về từ getMailer() theo một biến env (ví dụ MAILER=resend). Auth routes không phải sửa.
  2. Thêm API key / SMTP credential vào Environment của Render.
  3. Đặt AUTH_REQUIRE_EMAIL_VERIFICATION=true → deploy lại.
  4. Đăng ký thử một account thật, bấm link trong mail, rồi mới mở đăng ký công khai.

8 Vận hành & chi phí

Patch day

Thứ tự bắt buộc: dữ liệu static lên web trước, rồi mới refresh API — vì icon path trong Postgres trỏ vào apps/web/public/tft.

npm run fetch-data && npm run fetch-wisps && npm run fetch-loot
npm run fetch-comp-tips
git add packages/shared/data apps/web/public/tft
git commit -m "chore: patch data" && git push

Đợi Vercel xanh, rồi cron 19:00 (hoặc gọi tay) refresh API.

Refresh tay

curl -X POST \
  -H "Authorization: Bearer $REFRESH_TOKEN" \
  https://<api>/api/tft/refresh

Cron chạy 12:00 UTC mỗi ngày. Đọc log job trong Render dashboard — curl không --fail nên job vẫn xanh dù API trả 401/409/503.

Log & rollback

Log: Render → service → Logs; Vercel → Deployment → Functions/Runtime Logs.

Rollback web: Vercel → Deployments → chọn bản trước → Promote. Rollback API: Render → Events → deploy lại commit cũ, hoặc revert trên main.

Giới hạn cần nhớ

  • Vercel rewrite ra ngoài: trần 120 s mọi plan; proxyTimeout 90 s chỉ có giá trị trong trần đó.
  • Coach AI: 45 s/câu; TTS 45 s/chunk. Câu dài nhiều chunk thì cộng dồn — đo trên deployment thật.
  • Supabase Free: 500 MB, project pause sau 7 ngày không hoạt động.
  • Vercel Hobby cấm dùng thương mại; có ads/donate là phải Pro.

Dọn sau lần đăng nhập đầu

  • Xoá ADMIN_SEED_PASSWORD (và có thể cả ADMIN_EMAIL) khỏi Render env — hai biến này chỉ dùng để bootstrap admin đầu tiên.
  • Không bao giờ đặt DATABASE_URL hay key API vào env của Vercel — web không cần.
  • Xác nhận /admin chỉ vào được bằng account role = admin.
